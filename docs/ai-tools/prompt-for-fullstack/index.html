全栈工程师提示词模板库

学习目标​

学会用结构化提示词控制 AI 输出的代码质量，模板与本课程技术栈（React 18 + TypeScript、Spring Boot 3 + Java 17）对齐，填入需求即可使用。

通用提示词结构​

一套稳定的 Prompt 通常包含四部分：

角色：你是谁、熟悉什么技术栈
任务：要生成或解决什么（具体需求）
约束：版本、分层、依赖、错误处理、注释要求
输出：代码格式、是否附带说明与调用示例

模板 1：React 组件生成​

你是资深 React + TypeScript 工程师，技术栈为 Vite + Zustand + React Query。
需求：【在此填写组件/页面需求】
要求：
1. 函数组件，TypeScript 类型完整，避免 any；
2. 包含基础 loading 与错误处理；
3. 不引入额外复杂状态库；
4. 关键逻辑加注释；
5. 最后给出组件使用示例。

模板 2：Spring Boot 后端接口​

你是 Spring Boot 3 + Java 17 后端工程师，使用 Maven + Spring Data JPA。
需求：【在此填写接口需求，如：对话记录的新增与分页查询】
要求：
1. 分层清晰：Controller / Service / Repository / Entity / DTO；
2. 统一返回 ApiResponse 包装；
3. 入参使用 @Valid 校验；
4. 业务异常由全局处理器统一转换；
5. 输出完整可编译代码，并附 curl 调用示例。

模板 3：报错排查​

下面代码出现报错：【粘贴完整报错信息】
技术栈：【React TS / Spring Boot 3 / 其他】
相关代码：【粘贴代码】
请：
1. 定位根本原因；
2. 给出修复后的完整代码；
3. 用通俗语言解释原因（面向基础薄弱的开发者）；
4. 说明如何避免同类问题。

模板 4：RAG / Agent 能力实现​

基于 Spring Boot 实现 RAG 检索接口：接收用户问题，先检索知识库片段，再拼装上下文调用大模型，以 SSE 流式返回回答。
要求：
1. 分层清晰，检索、模型调用、消息组装解耦；
2. 预留工具调用（Function Calling）扩展位；
3. 密钥从配置/环境变量读取，不硬编码；
4. 附带接口调用示例与流程说明。

模板 5：代码解释与重构​

请阅读下面这段代码：【粘贴代码】
1. 用通俗语言逐段解释它做了什么；
2. 指出潜在问题（边界条件、性能、可读性、类型安全）；
3. 给出重构后的版本，并说明每处改动的理由；
4. 保持原有功能不变。

使用建议​

  • 先小后大：先用模板生成单个组件/接口，跑通后再组合；
  • 给足上下文：把相关类型、接口约定、报错一起提供，输出更准确；
  • 迭代追问：第一轮结果不理想时，追问「补充错误处理」「改成函数式更新」「加上测试」；
  • 落地校验：生成代码必须经过本地编译、运行与审查，再进入项目。

实践任务​

  1. 任选一个模板，填入自己的需求，生成一段代码并在本地调试跑通；
  2. 用模板 3 把你遇到过的一个真实报错整理成排查提示词；
  3. 对照AI 集成模块，用模板 4 描述你想扩展的一个 AI 功能。

工具与模板只是提效手段：课程各章节的基础概念仍然需要理解，AI 生成的代码最终要由你负责。回到学习路线图继续系统推进。
