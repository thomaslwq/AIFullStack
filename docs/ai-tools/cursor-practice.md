# Cursor：AI 编辑器辅助全栈开发

## 学习目标

掌握 Cursor 的基本交互方式，能用指令生成 React 组件与 Spring Boot 接口；会让 AI 解释代码、排查报错；明确「AI 生成代码必须人工审查」的原则。

## 1. 它是什么

Cursor 是内置大模型的 AI 编辑器，基于 VS Code 衍生，兼容 VS Code 扩展与快捷键。典型用途：

- 根据一句话需求生成组件、Controller、实体类；
- 解释看不懂的代码（零基础辅助理解）；
- 补全接口、DTO、TypeScript 类型；
- 根据报错日志定位与修复问题；
- 重构、加注释、补单元测试。

## 2. 基础指令示例（可直接改用）

**前端需求：**

```text
用 React + TypeScript + Zustand 写一个简单登录页面：包含用户名/密码表单、非空校验，提交后调用登录接口。给出完整组件代码，并说明每个部分的作用。
```

**后端需求：**

```text
用 Spring Boot 3 + JPA 写一个对话记录实体 ChatRecord，以及对应 Controller，提供新增和分页查询接口，返回统一 JSON 结构，参数加 @Valid 校验。
```

**排错需求：**

```text
下面这段代码报 CORS 跨域错误。技术栈是 Spring Boot 3 + React。请先定位原因，再给出修复后的完整代码，并用通俗语言解释。

[粘贴报错信息]
[粘贴相关代码]
```

## 3. 零基础正确使用姿势

1. **先看懂再运行**：不要无脑复制整段代码；让 AI 逐段加注释，自己能讲清每段作用；
2. **拆小需求**：一次让 AI 完成一个组件或一个接口，比要求「做整个系统」输出更可控；
3. **要求约束**：明确技术栈版本、不要引入额外库、附带错误处理与注释；
4. **报错直接贴**：把完整报错信息与相关代码一起发给 AI，定位更准；
5. **对照课程校验**：生成代码后回到对应章节（React Hooks、Spring Boot 分层）核对写法是否一致。

## 4. 生成代码的审查清单

- [ ] 依赖版本与本课程一致（Spring Boot 3 / JDK 17 / React 18）；
- [ ] 密钥、密码等敏感信息没有硬编码；
- [ ] 入参有校验，异常有处理；
- [ ] 类型标注完整，没有 `any` 泛滥；
- [ ] 本地能编译、能跑通示例请求。

## 实践任务

1. 在 Cursor 中让 AI 生成一个 React 计数器组件，运行验证；
2. 让 AI 为该组件补充注释与一个简单测试；
3. 对照[Hooks 章节](../frontend/hooks.md)检查状态写法是否规范。

## 常见坑

- **版本不匹配**：AI 可能按 Spring Boot 2 或旧版 React 生成代码，拿到后核对依赖与 API；
- **过度抽象**：练习项目不要让 AI 引入复杂状态库或设计模式，保持最小实现；
- **直接上线未审查**：AI 可能生成不安全或带缺陷的代码，必须人工审查与测试；
- **需求太笼统**：「写个后台管理系统」会得到难以落地的输出，应拆成具体页面/接口。
