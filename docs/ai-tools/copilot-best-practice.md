# GitHub Copilot 全栈开发最佳实践

## 学习目标

掌握 Copilot 在 React 与 Java 日常开发中的辅助方式；学会用注释与上下文引导生成质量；清楚哪些 AI 产出必须人工把关。

## 1. 开启方式

在 VS Code 安装 **GitHub Copilot** 与 **Copilot Chat** 扩展，登录 GitHub 账号后即可使用。补全在编辑时内联出现，Chat 用侧边对话或 `@` 指令交互。

## 2. 适合本课程的场景

| 场景 | Copilot 辅助方式 |
| --- | --- |
| Java 实体、DTO、Mapper 样板 | 根据字段名生成 getter/setter、校验注解 |
| React 组件、请求函数、TS 类型 | 依据 props 与状态推导类型与结构 |
| 单元测试 | 为 Service / 工具类生成测试用例骨架 |
| Dockerfile、脚本、配置 | 生成常见部署与构建脚本 |
| 代码解释 | 选中代码用 Chat 解释作用与执行流程 |

## 3. 用注释引导生成（关键技巧）

Copilot 依据上下文与注释预测代码。先写清晰的方法注释，补全结果会更符合约定：

```java
/**
 * 保存对话记录
 * @param dto 对话内容（必须包含会话 id 与消息文本）
 * @return 保存后的记录 id
 * 要求：参数非空校验；统一返回 Result；抛出业务异常由全局处理器处理
 */
@PostMapping("/chat/save")
```

注释写清输入、输出、约束后，再让 Copilot 补全方法体，生成的代码与团队规范更一致。

前端同理，先用注释描述组件职责与 props：

```tsx
/**
 * 消息气泡组件
 * @param role  'user' | 'assistant'
 * @param content 消息文本
 */
```

## 4. 提升补全质量的习惯

- 保持文件小而聚焦，相关类型与函数放在邻近位置；
- 命名清晰，避免模糊的 `data`、`handle`；
- 先写类型定义与接口，再让 Copilot 补实现；
- 多次生成时用 Tab 接受合适片段，不理想就继续打字引导；
- 用 Copilot Chat 做「解释这段代码」「给这段加错误处理」「补一个边界用例」。

## 5. 安全与质量边界（务必遵守）

- **不复制密钥**：不要把真实 Token、密码、内网地址贴进 AI 对话；
- **生成代码必须审查**：Copilot 可能产出硬编码凭证、SQL 拼接、不安全校验；
- **许可证与版权**：关注生成代码与开源许可证的合规要求；
- **测试兜底**：AI 生成的核心逻辑要有单元测试覆盖，不能只靠「看起来能跑」。

## 实践任务

1. 新建一个 Java DTO，先写字段注释与校验说明，让 Copilot 生成字段与 Validation 注解；
2. 为一个纯函数让 Copilot 生成边界用例测试；
3. 选中一段课程示例代码，用 Chat 让它解释执行流程，对照原文核对理解是否正确。

## 常见坑

- **补全跑偏**：上下文太少或命名不清；补充类型、注释后再试；
- **生成旧版 API**：与 Cursor 篇相同，核对依赖版本；
- **过度依赖补全**：练习阶段应先自己写，卡住时再参考 AI 建议，避免跳过基础训练。
